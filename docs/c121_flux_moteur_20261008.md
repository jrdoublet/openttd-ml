# C121 — flux reçu par les stations, mesure externe du 8 octobre

## Ce que mesure le compteur

OpenTTD 15.3 ajoute `amount` au `supply` du nœud de station au moment où
du nouveau cargo est effectivement ajouté à sa file, après attribution aux
stations. Ce compteur ne dépend pas des embarquements observés et ne diminue
pas lorsqu'une file perd des passagers. Il mesure le **flux capté sous le
service observé**, pas la production totale d'une ville ni la demande sous
une flotte hypothétique.

Sources moteur : [ajout de cargo et UpdateSupply](https://github.com/OpenTTD/OpenTTD/blob/15.3/src/station_cmd.cpp#L4055-L4083),
[compression et fusion](https://github.com/OpenTTD/OpenTTD/blob/15.3/src/linkgraph/linkgraph.cpp#L58-L99),
[format sauvegardé](https://github.com/OpenTTD/OpenTTD/blob/15.3/src/saveload/linkgraph_sl.cpp).
Dans les sauvegardes courantes, le chunk est **LGRP**, pas LGRA (ancien format).
Ne pas lire LGRJ : il contient les copies de travail du calcul de CargoDist.

`supply` est comprimé et rééchelonné lors de fusions : sa différence brute
n'est donc pas toujours un flux. Le décodeur exige même graphe, mêmes nœuds,
même date de compression, même identité et date de construction de station,
compteurs cohérents et intervalle positif de 32 jours au maximum. Sinon il
retourne inconnu ; aucune correction arbitraire de compression ni zéro imputé.
Les nœuds portent des StationID directs. Le propriétaire est résolu via STNN,
les cargos sont conservés séparément. Le cargo PASS est identifié dans le log
du runtime (`label:PASS`), pas codé en dur dans le collecteur.

Cette mesure n'est pas exposée à NoAI. Elle peut valider un estimateur utilisant
les informations accessibles à l'IA ; elle ne peut pas devenir une entrée
cachée de ses décisions. Elle n'identifie pas à elle seule les pertes ou le
flux embarqué : elle supprime leur nécessité pour mesurer les arrivées locales.

## Livraison et pilote

`sweeps/station_supply.py` décode les snapshots et les différences qualifiées.
Le harnais courant et son lanceur proposent `--station-supply-telemetry`, OFF
par défaut, post-traitement mensuel des sauvegardes. Le module et l'option sont
figés/hashés avec le harnais ; les deux compagnies sont extraites séparément.
`keep` conserve son contrat tuple ; aucune boucle, sonde ou politique NoAI
n'est ajoutée pour ce compteur. Les résultats sont dans les checkpoints JSONL.

Pilote `c121_station_supply_pilot_20261008`, graine 42, un an, un duel :
complet/sain, 13 snapshots valides, 188 intervalles tous cargos dont 76 exacts
(38 PASS). 30 frontières absentes et 82 changements de graphe/compression
restent inconnus. Bundle

manifeste `37b45589a695daa0098d9e791687dafb8bb51a93422b279362d1ed000fd798b4`.

## Résultats du diagnostic long

Dix duels sur dix complets/sains, vingt compagnies à horizon complet,
aucun `failed_runs`. OpexAI est `earning_without_expansion` sur 999/2026,
`active` sur les autres ; ces issues sont conservées, pas des erreurs NoAI.
Défauts figés : C121 économie ON, moteur/catalogue courant ON, limite de flotte
OFF, sonde Squirrel OFF ; modifications locales préexistantes communes conservées.
73 512 intervalles tous cargos, 54 261 exacts ; **25 686 intervalles PASS
exacts**, sur 410 identités de station/partie. Les autres cargos ne sont pas
additionnés aux passagers. 18 398 intervalles avec changement de graphe ou
compression et 853 frontières absentes restent inconnus.

526 cas de prévision exploratoire : 346 développement / 180 réservés, ces
derniers sur **28 stations et trois graines**, pas 180 graines indépendantes.
Les années futures ont en moyenne 9,16 mois exacts (278,5 jours) dans le
lot réservé. **Zéro cas avec 12 mois exacts passés + 12 futurs** : aucune
qualification de prévision annuelle complète n'est revendiquée.

| Repère sur les mêmes 180 cas réservés | WAPE | Biais moyen pondéré |
|---|---:|---:|
| Proxy offert initial, nouvelles paires | 35,04 % | +1,97 % |
| Proxy avec rating passé observé | 44,91 % | +31,87 % |
| Moyenne des flux reçus sur l'année passée, oracle | **13,30 %** | −6,94 % |

WAPE = somme des erreurs absolues / somme des flux observés. L'oracle a
également moins d'erreur sur chacune des trois graines réservées : 11,42 %
(73), 12,74 % (314), 17,54 % (512). En développement : 32,88 %, 37,50 %,
13,61 % respectivement. Aucun facteur n'a été appris sur les graines réservées.
Les observations exactes sélectionnées ne reconstituent pas les mois manquants.

La piste utile est **un historique local du flux reçu**, séparé du débit des
avions, puis une allocation conservant le total de station. Remplacer le rating
prévu par le rating observé passé seul est ici une mauvaise piste. Le proxy
initial a de fortes erreurs locales : sur le lot réservé, 46 cas surestiment
de plus de 50 %, et 27 sous-estiment d'au moins un tiers. Sa quasi-absence de
biais agrégé n'implique donc pas que toutes les lignes soient correctement
dimensionnées. **Aucune baisse uniforme de demande ou de flotte n'est justifiée.**
Ce proxy partiel n'est pas le modèle C121 complet ; cette comparaison ne tranche
pas la surestimation des passagers transportables ni du renfort marginal.

Livré : compteur de validation plus informatif, diagnostic long terminé,
estimateur de référence hors moteur et comparaison temporelle sur graines
réservées. **Pas encore un meilleur estimateur opérationnel NoAI validé.**
L'oracle ne doit pas être branché dans l'IA. Restant : construire son équivalent
avec les informations NoAI, l'évaluer contre ces arrivées locales et préserver
la réponse contrefactuelle au service/concurrence avant un essai causal de flotte.
