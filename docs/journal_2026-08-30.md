## 30. Correctif double demarrage : les lignes a un train roulaient a zero

`OpexBuildTrains(..., startVehicles=true)` demarrait le convoi simple, puis
`OpexBuildLine` appelait une seconde fois `StartStopVehicle` au commit : le train
revenait a l'arret. La double voie passait deja `false` et n'etait demarree qu'une
fois. Le constructeur passe maintenant toujours `false`; le commit transactionnel
est l'unique point de demarrage pour un ou deux trains.

Preuve retrospective dans `opex_double_track_20y_5seeds.json` : **44/44** lignes
restees a un train avaient un profit vehicule nul. Smoke neuf, graine 42 x 5 ans :
les **3/3** lignes a un train ont un profit positif (24 311 / 2 055 / 5 161),
7/9 doubles, 0 `RX` / `XC`.

## 32. Contrat economie ↔ constructeur rail : plafond deux trains

Le modele testait auparavant 1 a 8 trains alors que le constructeur ne realise qu'un
train sur voie simple ou deux trains, chacun sur sa voie dediee. Une sonde de cout
(`rail_cost_probe=1`) mesure desormais les commandes de construction avec `AIAccounting` :
la portee est arretee avant la recherche A* de la seconde voie, sinon les tests de
pont/tunnel etaient comptes comme des millions de cout fictif.

Sur 97 lignes reussies (5 graines x 20 ans), 62 etaient modelisees avec plus de trains
qu'elles n'en ont construites. Les couts mesures sont tous non negatifs ; rapport
cout reel / capital modele : 0,51 sur les voies simples, 0,96 sur les doubles. Le
classement rail est donc borne a `MAX_RAIL_TRAINS = 2`; le controle de tresorerie de
la seconde voie reste separe et inchangé.

Validation 5 graines x 20 ans (`opex_rail_cap2_20y_5seeds.json`) : zero `RX`, `XC`
ou `SIGFAIL`; valeur moyenne 6,65 M -> 7,02 M (+5,6 %), note 608 -> 605. Le gain est
sous le plancher de detection, et les echecs de site augmentent (10 -> 24/an en
moyenne) car le classement choisit d'autres paires. **Correctif de contrat garde,
pas encore un gain de performance valide** : pas de nouvelle baseline sans banc 20x20.
