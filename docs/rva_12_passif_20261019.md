# RVA-12 — évaluateur passif Squirrel

`ai/OpexAI/rva_evaluator.nut:20` rattache clé de candidat → identifiant de
tentative → ligne construite. Les échecs sont journalisés ; un seul travail
d'observation est actif, les refus pour occupation sont visibles. Aucun objet
candidat ou ligne mutable n'est conservé dans le travail.

`OpexRvaEvalStep` utilise les réserves C67 existantes, découpe l'emprise par
élément du quai et la comparaison par gare/tuile, puis consomme le slack
disponible. Les compteurs d'appels/opcodes et leur périmètre sont exposés.
Le coût du dernier log/retour n'est pas compris dans `completed_ops` ; aucune
mesure d'un ancien cycle n'est attribuée au nouvel évaluateur.

Sous le seul bit 256, la sonde lit l'union réelle des quais, la couverture
native de nos gares, notes/stock, production ville et producteurs par tuile,
pour voyageurs et courrier séparés. La nouvelle gare est exclue du réseau
de référence. Le normalisateur vivant initial est le nombre de maisons
de la ville, **prior uniforme par maison**, avec incertitude de composition
et maisons multituile. L'inventaire pondéré complet de RVA-08 est le contrat
hors ligne plus précis ; aucune assimilation du compte API à un volume.

Distribution automatique, couverture non modifiée (API élargissant les appels
tuile à rayon 4), producteur non résidentiel, tarif manquant ou recouvrement
propre sans recettes marginales : `reference_fallback`. Le scénario sans
concurrents est annoncé ; aucune note adverse arbitraire n'est inventée.
Le débit dimensionnant reste physique ; l'incrément de cargo compagnie est
journalisé séparément. Le gain monétaire n'est disponible que pour les cas
couverts sans effet propre inconnu. Les recettes par unité proviennent du
modèle de ligne, pas d'une prétendue mesure de recettes finales par passager.

La collecte a lieu après la tentative, peut s'étaler dans le mois et porte
ses dates. Changement de mois : abandon explicite. Les maisons détruites pour
la gare ne sont pas reconstruites artificiellement : ce relevé est un état
postconstruction, pas une preuve contrefactuelle préachat. Les coûts des options
mail/extension restent ceux du dossier hors ligne RVA-11 ; pas d'activation.

`scheduler.nut:10` et `_recordRailAttempt` gardent les appels par
`RVA_CYCLE_PROBE`, faux au défaut. Aucun réglage ajouté ici, aucune valeur,
score, achat ou Save/Load modifié. Contrats `test_rva_evaluator.py:9`.
Compilation/exécution, couverture des travaux terminés et coût opcodes du
nouveau passif : **MESURE REQUISE**, via les commandes du rapport.
