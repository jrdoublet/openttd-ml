### 1.1. Niveaux et progression du QG (`UpdateCompanyHQ`)
- **Fichier et lignes :** `src/src/object_cmd.cpp:165-178`
```cpp
void UpdateCompanyHQ(TileIndex tile, uint score)
{
    if (tile == INVALID_TILE) return;

    uint8_t val = 0;
    if (score >= 170) val++;
    if (score >= 350) val++;
    if (score >= 520) val++;
    if (score >= 720) val++;

    while (GetCompanyHQSize(tile) < val) {
        IncreaseCompanyHQSize(tile);
    }
}
```

### 1.3. Génération et attribution du trafic (`TileLoop_Object`)
- **Fichier et lignes :** `src/src/object_cmd.cpp:673-725`
- **Fréquence du tile loop :**
  - Définie par `TILE_UPDATE_FREQUENCY = 1 << 8 = 256` ticks (`src/src/landscape.cpp:89-90`, `814-833`).
  - Dans OpenTTD, 1 jour = 74 ticks (`Ticks::DAY_TICKS`).
  - 1 an = 365 jours = 27 010 ticks. 1 mois moyen = 30,4167 jours = 2 250,83 ticks.
  - Chaque tuile subit donc $2 250,83 / 256 = 8,792$ boucles de tuile par mois ($105,51$ par an).
  - Comme le QG occupe un rectangle 2×2 (4 tuiles distinctes), les 4 tuiles subissent au total **35,17 boucles de tuile par mois** (soit **422,03 boucles de tuile par an**).
- **Formule de génération de cargaison :**
  - **Passagers (`object_cmd.cpp:697-708`) :**
    - Seuil : `GB(r, 0, 8) < (256 / 4 / (6 - level))` = $\lfloor 64 / (6 - \text{level}) \rfloor$.
    - Quantité : `amt = GB(r, 0, 8) / 8 / 4 + 1` = $\lfloor X / 32 \rfloor + 1$.
  - **Courrier (`object_cmd.cpp:713-724`) :**
    - Seuil : `GB(r, 8, 8) < (196 / 4 / (6 - level))` = $\lfloor 49 / (6 - \text{level}) \rfloor$.
    - Quantité : `amt = GB(r, 8, 8) / 8 / 4 + 1` = $\lfloor Y / 32 \rfloor + 1$.
- **Tableau de production exact par niveau :**

| Niveau QG | Seuil Score | Passagers / mois | Passagers / an | Courrier / mois | Courrier / an | Total pax+mail / an |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **1** | < 170 | 1,65 | 19,8 | 1,24 | 14,8 | 34,6 |
| **2** | 170 – 349 | 2,20 | 26,4 | 1,65 | 19,8 | 46,2 |

| **5** | ≥ 720 | 13,19 | 158,3 | 9,07 | 108,8 | 267,1 |

- **À quelle gare vont ces cargaisons ?**
  - `TileLoop_Object` utilise `StationFinder stations(TileArea(tile, 2, 2))` (`station_type.h:137`, `station_cmd.cpp:4559-4575`, `station_base.h:645-675`).
  - Toutes les gares dont le bassin de desserte (catchment) englobe le QG sont identifiées.
  - La fonction `MoveGoodsToStation` (`station_cmd.cpp:4599-4682`) distribue la cargaison :
    - Si une seule gare couvre le QG, elle reçoit toute la production proportionnellement à sa note de service : `amount *= first_station->goods[cargo].rating + 1; UpdateStationWaiting(...)` (`station_cmd.cpp:4631`).
    - Si plusieurs gares couvrent le QG (y compris des gares adverses !), la cargaison est partagée au prorata des notations de service. **Important :** le jeu n'accorde aucun privilège à la compagnie propriétaire du QG ; une gare concurrente mieux notée capturera une part des passagers de notre QG.

## 3. Estimation chiffrée du gain

### 3.1. Niveau du QG atteint par OpexAI à 3 ans
Les relevés de score d'OpexAI à l'horizon 3 ans (`performance_history`) dans la campagne de référence `v294g_mech_3x3_20261021.json` montrent des scores compris entre **524 et 696** (médiane ~580-600) :
- À score ~500 (score 350 à 519) : **Niveau 3** $\implies$ **34,6 passagers / an**.
- À score ~600 (score 520 à 719) : **Niveau 4** $\implies$ **52,8 passagers / an**.

### 3.2. Revenu moyen par passager de nos lignes
Les 55 lignes aériennes (principales pourvoyeuses de transport passagers d'OpexAI) créées dans `reference_seed42_r0.log.gz` affichent via `C121_BUILD` des revenus unitaires passagers (`pax_income`) compris entre £55 et £137 :
- Minimum : £55
- Maximum : £137
- **Moyenne : £84,87 / passager** (~ £85 / passager).
*(Sur lignes de trains de passagers, le trajet est beaucoup plus court, 30 à 80 tuiles, et le revenu unitaire est de l'ordre de £15 à £30 / passager).*

### 3.3. Calcul du gain annuel estimé
Application de la formule définie par le mandat : $\text{Gain} = \text{passagers/an} \times \text{revenu moyen par passager}$.

1. **Au score ~500 (Niveau 3 du QG) :**
   $$\text{Gain} = 34,6 \times £84,87 = \mathbf{£2\,936 / an} \quad (\mathbf{2,94\text{ k£/an}})$$
2. **Au score ~600 (Niveau 4 du QG) :**
   $$\text{Gain} = 52,8 \times £84,87 = \mathbf{£4\,481 / an} \quad (\mathbf{4,48\text{ k£/an}})$$
3. **Moyenne sur l'intervalle score 500 – 600 :**
   $$\text{Gain moyen} = \mathbf{£3\,708 / an} \quad (\mathbf{3,71\text{ k£/an}})$$

### 3.4. Prise en compte de la notation de gare (`rating`)
En conditions réelles de jeu, `MoveGoodsToStation` applique le facteur $(\text{rating} + 1) / 256$.
Avec une note de desserte typique d'aéroport de ~70 % :
- Niveau 3 net : $34,6 \times 70\% \times £84,87 = \mathbf{£2\,055 / an}$ (**2,06 k£/an**).
- Niveau 4 net : $52,8 \times 70\% \times £84,87 = \mathbf{£3\,137 / an}$ (**3,14 k£/an**).

### 3.5. Économie du déménagement éventuel
Si le QG devait être ultérieurement déplacé vers un hub plus important :
- La valeur de la compagnie OpexAI à 3 ans est de **2,5 M£ à 5,6 M£**.
- Le coût d'un déménagement (1 %) s'élève donc à **£25 000 à £56 000**.
- Pour un gain différentiel de quelques centaines de livres par an, un tel déménagement nécessiterait **plus de 10 ans** pour être amorti, détruisant massivement de la valeur.
