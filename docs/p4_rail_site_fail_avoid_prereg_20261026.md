## Cause du NO-GO technique sur le code réel

1. `ai/OpexAI/builder_rail.nut:1080–1191`, `OpexStationPlans` : la spirale historique parcourt les tuiles dans `STATION_SEARCH_RADIUS`, jusqu'à `MAX_STATION_PLANS` pour chaque longueur, contrôle les tuiles de quai et d'approche, le cargo et l'acceptation moteur `AIRail.BuildRailStation` **dans `AITestMode`** aux lignes 1143–1169. Un plan publié a **déjà** passé ces vérifications. Une nouvelle commande de prévalidation ferait doublon ; l'observation shadow ne dispose pas d'une liste de sites refusés individuels à réutiliser sans instrumenter ce scan.
2. `builder_rail.nut:1473–1503` (`OpexRailTryPlatformLength`) et `:1521–1622` (`OpexRailPlatformPlans`) : après cas stricts de jonction V178/V264, toutes les longueurs entières de `wanted` jusqu'au minimum sont essayées ; le premier couple de listes A/B non vides à **longueur commune** renvoie `OK`. Les motifs `SITEA`, `SITEB` et `SITEAB` sont renvoyés **après épuisement** de ces solutions. Le fallback de jointure stricte est délibérément interdit pour ne pas contourner une gare partagée ni `_tooClose` (`ai/OpexAI/lines.nut:317–369`). Un nouveau quai après `SITE*` impose de changer le périmètre des sites, le contrat de jointure ou le modèle de longueur.
3. `builder_rail.nut:2179–2186` (`OpexCreateSegmentedSearch`) transforme **tous les plans validés disponibles** en sources et buts du **même A***. Réordonner un site déjà présent ne révèle pas une alternative à un `SITE*` ; les variantes élargissant le vivier V307S ont déjà échoué à leur exposition. V307R a dégradé les autres coûts/abandons. Interdiction de réactiver ces variantes sous un autre nom.
4. `builder_rail.nut:2557–2609` (`OpexRailRefreshExactPlatforms`) : après un A* déjà payé, la réparation géométrique conserve obligatoirement `station_exit`, `lead` et la **même longueur** de chaque gare ; ce contrôle protège le plan physique. Une gare ailleurs demanderait de recalculer la voie. Le cas `STNFAIL` à la cotation dispose déjà de cette tentative de rafraîchissement exact (`builder_rail.nut:4775–4794`), mais il ne fournit pas un remplacement de `SITEA/B/AB` avant A*.
5. `task_rail.nut:764–835`, `builder_rail.nut:4228–4275`, `:4506–4528` : un `SITE*` arrête `OpexPrepareRailRoute` **avant toute recherche** (`plansA == null`). Aucune paire alternative physiquement prévalidée n'est gardée dans un état permettant une substitution. `task_rail.nut:1105–1188` journalise la tentative, puis `:1342–1350` abandonne la paire. Le code ne contient donc pas de voie saine « une substitution de site, mêmes contrôles, un A* » pour cette cause. Ne pas confondre `RAIL_ATTEMPT reason=SITE*` avec un échec d'une gare précise : il décrit l'absence globale de solution de sites dans cette tentative.

**Obstacle bloquant** : satisfaire simultanément « un site alternatif **hors** du vivier épuisé », « aucun élargissement de la recherche V307 », « même longueur et jointure », et « aucun nouvel A* » est impossible avec ces interfaces. Conserver une mémoire ne construit pas un site de remplacement ; cela reproduirait le bannissement V294g. Pour rouvrir P4, il faudrait une preuve indépendante de **sites valides omis par une erreur de validation dans le domaine actuel**, avec `anchor`, cargo, côté, longueur, commande moteur, identité de gare et prix, et une interface existante permettant de les injecter avant le même A*. Aucun élément de ce type n'est établi par les `SITE*` agrégés.
