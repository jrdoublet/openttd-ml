### F-RAIL-ECON-02 — régression du défaut `rail_terrain_factor` et porte isolée 100→170

Le diagnostic F-RAIL-ECON-01 expose bien `rail_depot_cost` : sur les trois graines,

prévu ci-dessus, sans constituer une qualification économique du dépôt.

L'historique Git lève l'ambiguïté 170/100. Le commit `b26fb31` du 02/09 a introduit
`rail_terrain_factor` avec **170 par défaut**, après calibration physique du coût réel
de voie. Le commit `58fce9f4` du 26/09, intitulé **« adopt finance bias 100 »**, a
correctement passé `rail_finance_bias_pct` 170→100, mais a simultanément changé les
valeurs `easy/medium/hard/custom` de `rail_terrain_factor` 170→100. Le texte du même
commit continue pourtant d'affirmer que `candidate.capital` inclut déjà
`RAIL_TERRAIN_FACTOR=170`, et les documents d'architecture ultérieurs distinguent
toujours financement rail 100 / facteur terrain 170. Conclusion : **100 est une
régression de défaut introduite avec l'adoption du biais de financement**, pas une
nouvelle calibration documentée.

Avant tout edit du défaut, le retour 100→170 est donc testé isolément sur le code
live courant, sans `decision_log`, selon V102 :

- référence `OpexAI[rail_terrain_factor=100]` ; variante

Le but de cette porte n'est pas de « sauver » `rail_depot_cost` mais de rétablir ou
rejeter séparément la calibration physique du rail. `rail_depot_cost` ne sera repris
