## Regroupement des sondes en 9 macros `probe_*`

Le commit GitHub `531cca6`, fusionné par le PR #9 (`53b6ddf`), réduit la surface de configuration
diagnostique : **70 réglages de sonde individuels sont regroupés en 9 macro-réglages `probe_*`**
dans `info.nut` et `settings.nut`.

La relecture du chantier trouve et corrige trois problèmes importants :

1. dix-sept scripts `sweeps/*.py`, dont les runners B9/M3/M4, utilisaient encore les anciens noms
   de sondes ; ils sont remappés vers les macros ;
2. les deux listes blanches historiques de `bench_v2.py`, devenues redondantes avec le parsing de
   `info.nut`, sont supprimées ;
3. une garde eau perdue est restaurée : activer une macro de probe catalogue ne doit pas déclencher
   par accident un vrai `OpexWaterPlans()` coûteux si le précontrôle eau n'est pas demandé.

`diag_c39_events.py` est réécrit pour dériver son audit des réglages réellement envoyés au lieu de
maintenir une reconstruction parallèle. `test_campaign_freeze.py` saute proprement son test Git
quand Git n'existe pas dans le runtime Docker.

La documentation dédiée `docs/walkthrough_regroupement_probes.md` explique le mapping, les pertes
de granularité assumées et les corrections trouvées après coup.

Validation explicitement enregistrée dans le commit : **23 tests unitaires verts** sur les suites
campaign freeze/B9/M3, puis smoke Docker des neuf sondes identique bit à bit au contrôle sans sonde
après restauration de la garde eau.
