## 1. Chemin

`OpexC117AirThroughputStep` ([probes.nut](../ai/OpexAI/probes.nut)) tourne tous les
`C117_AIR_SAMPLE_DAYS` = 2 jours dès que la sonde C117 **ou** C121 économie/shadow
est actif. Au défaut, `c117_air_throughput_probe=0` et `c121_air_economics=1` :
l'échantillonnage alimente C121, pas le journal C117.

Appelants : [main.nut](../ai/OpexAI/main.nut) (boucle principale, span `loop.c117`)
et le chemin parallèle dans `probes.nut` (profil opcodes).

```
OpexC117AirThroughputStep
  └─ par ligne AIR, tous les 2 jours
       ├─ scan véhicules (profit, pax, sièges, trips, wait, hub residual)
       └─ changement de seau 30 j → OpexC117FlushLine
            ├─ OpexC121HubDelayFlushLine          (C121 économie)
            ├─ OpexC121FirstLiveObserve           (garde 1→2)
            └─ chaîne ~110 champs + AIAirport     (journal C117 seulement)
```

Réglage `c117_lean_sampling` (0/1/2, quatre `*_value` = 0), globale
`C117_LEAN_SAMPLING`. Lecture : `GetSetting` avec garde `>= 0` (un nom inconnu
renvoie −1).

| Mode | Sonde C117 | Échantillonnage | Flush | Observe |
|---|---|---|---|---|
| 0 (défaut) | off ou on | historique, y compris extras | chaîne complète | position historique (après `profitCapitalPm`, avant `AIAirport`) |
| 1 | off | C121 + hub delay seulement | HubDelay + Observe, puis sortie | après HubDelay |
| 1 | on | historique | chaîne complète | position historique |
| 2 | off | historique **et** vue lean | compare, Observe sur l'historique, sortie | après compare |
| 2 | on | historique | chaîne complète | position historique |

## 3. Mode 2

Quand `c117_lean_sampling=2` et sonde éteinte :

1. L'échantillonnage historique écrit tout `state` (chemin utilisé).
2. Les champs C121/hub sont aussi accumulés dans `state.leanView`.
3. Au flush : `OpexC117CompareLeanSampling` compare les deux vues champ par champ.
   Chaque écart : `OpexDecide("C117_LEAN_MISMATCH", "line=… field=… hist=… lean=…")`.
4. Total mensuel sous `DECISION_LOG` : `OpexDecide("C117_LEAN_MISMATCH", "month=… total=…")`,
   compteur remis à 0.
5. `OpexC121FirstLiveObserve(line, state, …)` lit l'historique.

Limite : la vue lean est alimentée dans **la même passe** que l'historique, à
partir des mêmes incréments C121. Cela détecte un oubli de dual-write. Cela ne
relance pas un second scan véhicule (l'état `C117_AIR_VEHICLE_STATE` est global).
L'omission d'un champ C121 derrière `skipUnused` est attrapée par les contrats
statiques (mode 2 a `skipUnused=false`).

## 6. Risques

- Un futur lecteur d'un champ sauté (ratings, `lastEngine`, mail de ligne)
  changerait C121 ou le hub delay à 1. Les contrats listent les lecteurs.
- À 0, `AICargo.IsValidCargo` passe à une fois par échantillon au lieu d'une
  fois par avion. Décisions identiques ; opcodes du défaut légèrement en baisse
  sur ce test invariant.
- À 0, quelques `if (!skipUnused)` / `if (dualCompare)` restent des branches
  fausses. Coût négligeable devant 8,4 k/échantillon.
- Mode 2 n'est pas un second scan indépendant (voir §3).
- Pas de 20×10, pas d'adoption. Règle opcodes : gain mesuré puis 20×10 neutre.
